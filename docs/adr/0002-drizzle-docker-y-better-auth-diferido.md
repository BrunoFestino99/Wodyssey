# Drizzle, Docker y Better Auth diferido

El backend reemplaza las consultas SQL manuales con `pg` por Drizzle ORM, con el esquema definido en TypeScript y migraciones generadas con `drizzle-kit`. Se adopta ahora, antes de modelar programas, sesiones, bloques, trabajos, asignaciones y resultados, porque el dominio relacional va a crecer y el esquema tipado evita que consultas y tablas se desincronicen. Como no hay datos desplegados, las tres migraciones SQL existentes se sustituyen por una migración inicial de Drizzle, que se sigue aplicando al arrancar la API.

Docker se usa para producción y para desarrollo: una imagen para la API y otra que sirve la web compilada, independientes del proveedor de hosting, que sigue sin definirse. El desarrollo puede ejecutarse completo con Docker Compose o con `npm run dev`, que pasa a usar el PostgreSQL de Docker o un `DATABASE_URL` propio. Se elimina `embedded-postgres`: las pruebas E2E corren contra el PostgreSQL de Docker y la integración continua corre solo en Linux, porque los ejecutores Windows de GitHub no ejecutan imágenes Linux.

Se descarta por ahora reemplazar la autenticación propia por Better Auth. La autenticación actual cubre el alcance del MVP (correo y contraseña con verificación y recuperación) y está probada; Better Auth se incorporará junto con el acceso con Google y Apple, cuando sus proveedores, la vinculación de cuentas y el uso desde Flutter justifiquen reemplazarla. Esa migración debe conservar el comportamiento verificado por las pruebas E2E de acceso, y el término del dominio sigue siendo **Cuenta**, aunque la biblioteca la llame `user`.
